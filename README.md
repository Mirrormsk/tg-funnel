# tg-funnel — мини-воронка регистраций в Telegram

Бот на aiogram 3 собирает регистрации, отправляет цепочку сообщений по расписанию, а Telegram Mini App показывает статистику воронки.

```
/start → приветствие → запрос телефона (кнопка) → регистрация
                                                    ├─ +10 сек: сообщение 1
                                                    └─ +1 мин:  сообщение 2
/stats → кнопка «Открыть дашборд» (Mini App)
```

## Быстрый старт

Нужны Python 3.12+ и [uv](https://docs.astral.sh/uv/).

```bash
cp .env.example .env        # вписать BOT_TOKEN от @BotFather и свой Telegram ID в ADMIN_IDS
uv sync
uv run python -m app.main   # бот + планировщик + дашборд на http://127.0.0.1:8080
```

### Дашборд внутри Telegram

Telegram открывает Mini App только по HTTPS, поэтому локальный сервер нужно пробросить туннелем:

```bash
brew install cloudflared
cloudflared tunnel --url http://localhost:8080
# → https://xxxx.trycloudflare.com — вписать в WEBAPP_URL в .env и перезапустить бота
```

Потом отправить боту `/stats` и нажать «Открыть дашборд».

Чтобы посмотреть дашборд в обычном браузере без Telegram, запустите с `DEV_MODE=true` (проверка доступа отключается, только для локальной разработки).

## Конфиг

Все тексты и тайминги лежат в [`config.yaml`](config.yaml). Тексты пишутся в HTML-разметке Telegram, а в приветствие подставляется `{name}`. Шагов в `schedule` может быть сколько угодно: дашборд строит воронку по ним автоматически. При запуске конфиг валидируется через pydantic, поэтому ошибка в YAML (например, повторяющийся `id` или отрицательная задержка) остановит запуск с понятным сообщением.

## Как устроено

| Файл | Что делает |
|---|---|
| `app/main.py` | Точка входа: бот (polling), планировщик и FastAPI в одном event loop |
| `app/bot.py` | Хендлеры: `/start`, контакт, `/stats`, напоминание для тех, кто не дал номер |
| `app/scheduler.py` | Раз в секунду отправляет сообщения, у которых подошло время |
| `app/db.py` | SQLite: пользователи, очередь сообщений, агрегаты для дашборда |
| `app/auth.py` | Проверка подписи `initData` от Mini App |
| `app/web.py` | `GET /` — дашборд, `GET /api/stats` — статистика |
| `webapp/index.html` | Дашборд: HTML + JS без сборки, цвета из темы Telegram, автообновление каждые 3 с |

**Решения, которые стоит отметить:**

- **Очередь сообщений лежит в БД, а не в `asyncio.sleep`.** Если перезапустить бота, ничего не потеряется: просроченные сообщения уйдут сразу после старта. Повторная отправка номера не создаёт дублей цепочки (`UNIQUE(user_id, step_id)`).
- **Ошибки доставки обрабатываются.** Если пользователь заблокировал бота, сообщение помечается как `failed` и видно в дашборде. Если Telegram ответил `RetryAfter`, сообщение переносится, а не теряется.
- **Принимается только свой номер.** Через «Прикрепить → Контакт» можно отправить чужой контакт, такой номер бот отклоняет.
- **Дашборд защищён.** API проверяет HMAC-подпись `initData`, срок её действия (24 ч) и `ADMIN_IDS`. Телефоны в дашборде маскируются.
- **SQLite выбран ради локального запуска без зависимостей.** Для продакшена слой `Database` можно перевести на PostgreSQL, не меняя хендлеры.

## Тесты

```bash
uv run pytest
```

Покрыто: расписание отправки (10 с / 60 с, без повторов), защита от дублей, пометка недоставленных сообщений, агрегаты статистики, маскировка телефонов, проверка `initData` (валидная подпись, чужой бот, устаревшие данные, не админ).
